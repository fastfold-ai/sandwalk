**Dashboard → MCPs** manages Model Context Protocol (MCP) servers stored in `~/.sandwalk/mcp.json`. Sandwalk uses the standard **Cursor / Claude Desktop `mcpServers` JSON format**, so you can paste any Cursor `mcp.json` configuration directly into Sandwalk (or copy Sandwalk's `mcp.json` into Cursor).

---

## Cursor-Style `mcp.json` Structure (`~/.sandwalk/mcp.json`)

Click **`</> Edit mcp.json`** in the top-right corner of **Dashboard → MCPs** (or open `~/.sandwalk/mcp.json` in any editor) to inspect or edit all configured servers in one JSON file:

### Example `~/.sandwalk/mcp.json`

```json
{
  "mcpServers": {
    "omnigraph": {
      "command": "/Users/you/.sandwalk/bin/sandwalk-omnigraph-mcp",
      "args": [],
      "type": "stdio",
      "description": "Local Omnigraph v0.13.0 knowledge graph engine (7 tools: query, upsert_node, record_claim, branch, load_cookbook_seed, sync_bundle).",
      "_sandwalkCatalogId": "omnigraph"
    },
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/you/Projects"],
      "type": "stdio",
      "description": "Local filesystem MCP server via npx."
    },
    "latch": {
      "url": "https://mcp.latch.bio/mcp",
      "type": "http",
      "description": "Bioinformatics workflows, data, and compute on the Latch platform.",
      "_sandwalkCatalogId": "latch"
    },
    "custom-remote-mcp": {
      "url": "https://mcp.example.com/mcp",
      "type": "http",
      "headers": {
        "Authorization": "Bearer YOUR_TOKEN"
      },
      "disabled": false,
      "description": "Custom Streamable HTTP MCP server with custom headers."
    },
    "linear": {
      "url": "https://mcp.linear.app/mcp",
      "type": "http",
      "disabled": true,
      "description": "Issues, projects, and comments for product and ops workflows.",
      "_sandwalkCatalogId": "linear"
    }
  }
}
```

## `mcpServers` Entry Field Reference

Every key under `"mcpServers"` is the server's identifier (`"omnigraph"`, `"latch"`, `"linear"`, or any custom name):

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | `"stdio"` \| `"http"` \| `"sse"` | Optional | Transport protocol. Inferred automatically as `"stdio"` when `command` is present, or `"http"` (Streamable HTTP) when `url` is present. Use `"sse"` for legacy Server-Sent Events endpoints. |
| `command` | `string` | For `stdio` | Executable name or absolute path (e.g., `"npx"`, `"uvx"`, `"python3"`, or `"/Users/you/.sandwalk/bin/sandwalk-omnigraph-mcp"`). |
| `args` | `string[]` | Optional | Command-line arguments passed to `command` (defaults to `[]`). |
| `url` | `string` | For `http` / `sse` | Remote MCP endpoint URL (e.g., `"https://mcp.latch.bio/mcp"`). |
| `headers` | `Record<string, string>` | Optional | Custom HTTP headers (such as `Authorization: Bearer ...`) for custom remote servers. |
| `disabled` | `boolean` | Optional | Set to `true` to keep the server in `mcp.json` while disabling it at runtime. (`"enabled": true/false` is also accepted when pasting.) |
| `description` | `string` | Optional | Human-readable summary shown on the server card in **Dashboard → MCPs**. |
| `_sandwalkCatalogId` | `string` | Optional | Links a catalog-seeded entry (`omnigraph`, `latch`, `tamarind`, `neurosnap`, `paperclip`, `linear`, etc.) to Sandwalk's built-in catalog metadata and **Dashboard → Integrations** credential store so OAuth tokens and API keys are never written in plaintext into `mcp.json`. |

## Built-in Local Omnigraph MCP (`omnigraph`)

When you install Omnigraph in **Dashboard → Memory & Wiki** (or enable **Omnigraph** in **Dashboard → MCPs**), Sandwalk automatically generates the executable stdio bridge `~/.sandwalk/bin/sandwalk-omnigraph-mcp` and enables the `"omnigraph"` entry in `~/.sandwalk/mcp.json`.

It exposes 7 graph tools over stdio to your agents and Specialists:

- `omnigraph_status` — Inspect binary version (`0.13.0`), `.omni` Lance store path, and active Cookbook schema.
- `omnigraph_query` — Execute a Cookbook `.gq` stored query (`active_goals_and_tasks`, `contested_claims`, `decisions_at_risk`, etc.).
- `omnigraph_upsert_node` — Upsert a typed ontology node into the active Cookbook layer.
- `omnigraph_record_claim` — Record a provenance-backed `Supports` or `Contradicts` edge.
- `omnigraph_branch` — Create, list, merge, or delete Git-style graph branches (`main`, `review/*`).
- `omnigraph_load_cookbook_seed` — Load any of the 6 Cookbook starter graphs (`01–06`).
- `omnigraph_sync_bundle` — Export `schema.pg`, `queries.gq`, `SKILL.md`, and `data.jsonl` and sync into `graph.omni`.

## Using MCPs in the CLI & Composer

- **In the Composer**: Click `+ → MCP` to toggle which MCP servers are active for the current session, or attach specific MCP servers to a **Specialist** profile (**Dashboard → Specialists**).
- **From the CLI**:
  ```bash
  sandwalk mcp list
  ```
  Or type `/mcps` inside interactive `sandwalk` to connect, enable, validate, add, or remove MCP servers.
